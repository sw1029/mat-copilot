## 1. 개요 (Overview)
초기 유저 의도 정보가 주어진 경우 agent 기반 하위 질문 n개 생성 -> 각 질문별 하위질문 branch를 모호한 점이 해결될 때까지 지속 생성하여 모호한 유저 의도를 구체화한 뒤, 제공된 링크/파일의 결과물을 토대로 해당 초기 의도가 충족되었는지, 얼마나, 어느 지점에서 어긋났는지 확인 후 정량적 통계 생성 및 정성/정량 보고서 반환

## 2. 배경 및 문제 정의 (Background & Problem)
- 현재 상황: 유저 초기 의도는 모호하며, 초기 설계가 미흡하거나, 초기 설계를 원활히 수행하였더라도 ai에게 위임하는 경우 문서작업, 코딩, 기타 작업 등에서 발생하는 초기 의도와 다른 실수(의도되지 않은) 및 ai에게 작업을 위임한 경우 발생하는 할루시네이션 등을 사용자가 한 눈에 파악하기 힘들다. 
- 해결하려는 문제: 유저 초기 의도를 반복된 질의(deep interview)를 통해 상세 구체화 및 반복되는 질의에서 유형/무형적으로 확인 가능한 의식적/무의식적 유저의 의도를 추출하여 해당 의도 대비 유저가 제공한 결과물(문서, 작업 결과물, 코딩 결과물 등)가 얼마나 어긋난 형태인지 상세 보고하고, 해당 결과를 바탕으로 개선제안

## 3. 목표 및 비목표 (Goals & Non-Goals)
### 3.1 목표
- G1. 유저가 올린 docx/txt/md 등의 포맷을 가지는 기획안 등에서 tool use가 가능한 agent를 통해 초기 기획 추출
- G2. 초기 기획안이 없는 경우 agent를 통해 반복적 질의(이 경우 질문 담당 agent는 하나에 그치지 않고 여러 agent를 통해 질문 생성/검증 수행). 중간에 초기 의도 대비 변경된 요소가 있는지도 추가 질문(이를 통해 user의 confused 지점 파악 + 해당 지점 바탕으로 유저의 의식적/무의식적 의도 방향성 정성 추출)
- G3. 추출한 정보를 정규화
- G4. 정규화된 정보를 바탕으로 원하는 정량/정성 정보 추출
- G5. 추출된 정보를 태그/스키마/agent를 통한 정량/정성평가 정보를 도출
- G6. 도출된 정보를 토대로 유저가 제공한 결과물(문서, 작업 결과물, 코딩 결과물 등)가 얼마나 어긋난 형태인지 agent(분석 테마별 agent를 별도 운용)를 통해 분석
- G7. 분석결과를 바탕으로 정량 집계/정성 분석 결과를 시각화(이 경우 분석 테마별 agent를 따로 둘것)
- G8. 멀티테넌시/동시성 지원 — 로그인 없이 세션 단위로 식별되는 다중 유저의 동시 세션 처리

### 3.2 비목표
- NG1. 인증/인가는 수행하지 않음 (MVP 구현 우선, AGENTS.md "로그인 없이 동작" 제약과 정합)
- NG2. heavy job은 직접 실행하지 않음
- NG3. 시각화 렌더링은 백엔드 범위가 아님 (백엔드는 도표 구성용 데이터만 제공, 렌더링은 프론트 담당)
- NG4. 결과물의 자동 수정/수정 실행은 하지 않음 (개선 "제안"까지가 범위)
- NG5. 세션 간 유저 프로파일 학습/비교는 하지 않음 (schema/tag의 세션 단위 임의 생성과 정합)
- NG6. 운영/관리자 기능은 제공하지 않음 (해커톤 구현)

## 4. 사용자 및 이해관계자 (Users & Stakeholders)
| 구분 | 설명 | 백엔드에 대한 기대 |
| --- | --- | --- |
| 최종 사용자 | 구조화되지 않은 형식으로 즉흥적으로 작업을 수행하는 사용자 (ai에게 작업을 위임하는 경우 포함) | 초기 의도, 중간 의도 대비 최종 결과물이 얼마나 drift되었는지에 대한 정량/정성 분석 및 개선제안 제공 |
| 프론트엔드 | 인터뷰(질의응답) 진행 및 보고서를 가변 렌더링하는 클라이언트 | 질의/응답 루프, 유저 설정(질문 강도·시간 제한·request flag), 기획안/결과물 제출, 보고서 조회를 위한 API 및 plot용 도표 구성 정보(x/y축 이름, csv로 구성 가능한 정보) 제공 |
| 운영/관리자 | 해당 없음 — 해커톤 구현으로 제외 (NG6) | 없음 |

## 5. 핵심 시나리오 (User Stories)
| ID | 사용자 스토리 | 우선순위 |
| --- | --- | --- |
| US-1 | 기획안(docx/txt/md)을 보유한 사용자로서, 업로드한 기획안에서 agent가 초기 기획을 추출해 주기를 원한다. 왜냐하면 초기 의도를 별도 재작성 없이 분석 기준선으로 삼고 싶기 때문이다. (G1) | P0 |
| US-2 | 초기 기획안이 없는 사용자로서, 여러 agent의 반복적 질의(deep interview)를 통해 모호한 의도를 구체화하고 싶다. (G2) | P1 |
| US-3 | 작업 중 의도가 변한 사용자로서, 초기 의도 대비 변경된 요소에 대한 추가 질문을 받아 confused 지점과 의식적/무의식적 의도 방향성이 분석에 반영되기를 원한다. (G2) | P1 |
| US-4 | 사용자로서, 질문 강도(confuse threshold)와 시간 제한을 설정하고, 더 대답하고 싶은 요소가 있으면 request flag로 추가 구체화를 진행하고 싶다. | P1 |
| US-5 | 결과물(링크/파일)을 제출하는 사용자로서, 초기/중간 의도 대비 결과물이 얼마나·어느 지점에서 어긋났는지 정량/정성 분석을 받고 싶다. (G6) | P0 |
| US-6 | 사용자로서, 정량 통계와 정성/정량 보고서 및 개선제안을 받고 싶다. (G7) | P0 |

## 6. 기능 요구사항 (Functional Requirements)
| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| FR-1 | 기획안 업로드/추출 | docx/txt/md 포맷의 기획안을 수신하고 tool use가 가능한 agent로 초기 기획 추출 (MVP는 3종 고정, pdf 등 추가 포맷은 M2 검토) | P0 |
| FR-2 | Deep interview | 초기 기획안이 없는 경우 여러 agent를 통한 질문 생성/검증, 각 질문별 하위질문 branch를 지속 생성하여 의도 구체화 | P1 |
| FR-3 | 인터뷰 종료조건 제어 | 각 가지 질문의 confused 지표(agent가 산출)를 통해 하위 질문 생성 필요가 더 이상 제기되지 않을 때까지 + 유저가 설정한 질문 강도(confuse의 threshold 조정) 기준으로 종료. 단, 결과 산출에 필수적인 정성 결과는 agent 판단 하에 질문 가능하며, 필수 질문 외의 추가 임의 질문만 해당 종료조건의 대상. 감시 agent 혹은 임의 종료조건을 할당해 지나치게 길어지는 것을 방지하되, 유저 request flag가 있으면 추가 구체화 가능. confused 지표는 질문 생성 agent와 분리된 검증 agent가 가지(노드) 단위의 연속값(0~1)으로 산출하고 질문 강도는 그 threshold로 동작 (산출 산식 상세는 TRD) | P1 |
| FR-4 | 중간 의도 변경 감지 | 초기 의도 대비 변경된 요소에 대한 추가 질문으로 confused 지점 파악 + 해당 지점 바탕으로 유저의 의식적/무의식적 의도 방향성 정성 추출 | P1 |
| FR-5 | 정보 정규화 | 추출한 정보를 정규화. 정규화 schema/tag는 임의 생성하되 세션 내에서는 잠금(생성 후 고정)하며, 사용된 schema 명세를 보고서에 동봉 | P0 |
| FR-6 | 정량/정성 평가 | 정규화된 정보를 바탕으로 태그/스키마/agent를 통해 정량/정성 평가 정보 도출 | P0 |
| FR-7 | 결과물 수집/분석 실행 | 웹 페이지는 agent를 통해 분석. zip, docx 및 문서, 코드 파일 등(텍스트로 읽히는 파일 전반)은 sandbox로 분석. github는 read only로 분석. heavy job은 직접 실행하지 않음 | P0 (파일) / P1 (웹 페이지·github) |
| FR-8 | Drift 분석 | 분석 테마별 별도 agent를 운용하여 결과물이 의도 대비 얼마나·어느 지점에서 어긋났는지 분석. 테마는 고정 코어 4종(요구 누락, 의도 왜곡, 할루시네이션, 범위 초과) + agent가 동적 생성하는 보조 테마. 모든 판정에 결과물 내 근거 위치 인용을 의무화하고 근거가 없으면 저신뢰로 표기 | P0 (코어 1종) / P1 (코어 전체+동적 보조) |
| FR-9 | 집계/시각화 데이터 생성 | 정량 집계 결과와 plot을 위한 도표 구성 정보(x/y축 이름) 및 csv로 구성될 수 있는 정보 생성. chart type 선택은 프론트 자율(가변 렌더링) | P1 |
| FR-10 | 보고서 생성 | 정량 통계 및 정성/정량 보고서와 개선제안 반환. 정량 지표는 개수 기반(어긋난 지점 수, 커버된 요구 수 등)으로 한정하고 점수화는 정성 참고로만 사용 | P0 |
| FR-11 | 세션 관리 | 로그인 없이 session token 발급/식별 (AGENTS.md "로그인 없이 동작" 충족 수단), 다중 유저 동시 세션(멀티테넌시) 지원 (G8) | P0 |

### 6.1 API 개요
구체적인 Method/Endpoint 및 통신규약은 [SCHEMA/schema.md](../SCHEMA/schema.md), [TRD/back.md](../TRD/back.md)에서 확정. 인터뷰 질의/응답은 동기 또는 SSE 스트리밍, 분석 실행은 비동기 job + 상태 조회의 이원 구조. 인증/인가는 수행하지 않고 발급형 session token으로 세션을 식별.

| 기능 영역 | 설명 | 인증 |
| --- | --- | --- |
| 세션 발급 | 로그인 없이 session token 발급 (FR-11) | 불필요 |
| 기획안 업로드 | docx/txt/md 기획안 제출 (FR-1) | 불필요 |
| 인터뷰 질의/응답 | 질문 수신 및 답변 제출 루프 — 동기 또는 SSE (FR-2~4) | 불필요 |
| 유저 설정 | 질문 강도(confuse threshold), 시간 제한, request flag (FR-3) | 불필요 |
| 결과물 제출 | 링크(웹 페이지/github)·파일(zip, docx, 문서, 코드) 제출, 비동기 분석 job 생성 (FR-7) | 불필요 |
| 분석 결과/보고서 조회 | 분석 job 상태 조회, 정량 집계, 도표 구성 정보(x/y축 이름, csv 구성 가능 정보), 정성/정량 보고서, 개선제안 (FR-8~10) | 불필요 |

### 6.2 데이터 모델 개요
<!-- 주요 엔티티와 관계를 간단히 기술 (상세 스키마는 TRD) -->
- 인터뷰 세션: session token으로 식별. 유저 설정(질문 강도, 시간 제한) 포함. 질문 트리와 결과물, 보고서의 상위 단위
- 의도: 초기 의도(기획안 추출 또는 인터뷰 도출) 및 중간 변경 의도, 의식적/무의식적 의도 방향성(정성)
- 질문/답변: 질문별 하위질문 branch(트리 구조), 각 가지의 confused 지표, 필수/임의 질문 구분, request flag
- 정규화 정보: 임의 생성된 schema/tag로 정규화된 의도 정보
- 결과물: 웹 페이지 링크, github(read only), 파일(zip/docx/문서/코드)
- 분석 결과: 테마별(코어 4종 + 동적 보조) agent의 정량/정성 결과와 근거 인용, 비동기 분석 job 상태
- 보고서: 정량 통계, 정성 분석, 개선제안, 도표 구성 정보(x/y축 이름, csv 구성 가능 정보)

  - 백엔드는 시각화 렌더링을 하지 않으며 도표 구성용 데이터(x/y축 이름, csv 구성 가능 정보)만 제공
- 가정:
  - 유저는 결과물을 링크(웹 페이지/github) 또는 파일 형태로 제공 가능
  - 정규화 schema/tag는 사전 고정이 아닌 임의 생성으로 충분함
  - LLM 기반 agent(tool use, 다중 agent 운용) 사용을 전제
