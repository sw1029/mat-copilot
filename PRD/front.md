## 1. 개요 (Overview)
mat-copilot은 AI agent가 기획안 업로드 또는 deep interview로 사용자의 모호한 의도를 구체화하고, 그 의도를 기준선 문서(IntentDoc, Markdown)로 정리한 뒤, 사용자가 제출한 결과물(파일·링크·GitHub)이 의도 대비 얼마나·어느 지점에서 어긋났는지(drift)를 근거 인용과 함께 분석·보고하는 로그인 없는 웹앱이다.

프론트엔드는 React 기반의 전체 화면 고정형 웹 애플리케이션으로 구성한다. 사용자는 홈에서 기획안을 업로드해 인터뷰를 건너뛰거나 단축할 수 있고, 기획안이 없으면 한 번에 하나씩 제시되는 질문에 답하며 의도 기준선을 만든다. 질문 흐름은 백엔드가 반환하는 트리 관계를 따라 마인드맵으로 표현하며, 캔버스만 드래그하여 탐색한다.

핵심 화면 흐름은 `홈/기획안 업로드 또는 첫 질문 → 연속 질의 마인드맵 → 결과물 제출 → 분석 대기 → 분석 결과`다. 프론트 정적 번들은 백엔드 컨테이너(Azure Container Apps)에서 단일 URL로 서빙되어 별도 CORS 구성이 필요 없도록 한다.

## 2. 배경 및 문제 정의 (Background & Problem)
| 구분 | 내용 |
| --- | --- |
| 현재 상황 | 사용자의 초기 의도는 대체로 모호하며, AI에게 문서·코드·기타 산출물 생성을 위임하는 과정에서 요구사항 누락, 의미 변형, 범위 초과, 할루시네이션이 발생할 수 있다. |
| 사용자 문제 | 결과물이 원래 의도와 어디서 어긋났는지 수동으로 대조하려면 문서 10페이지·코드 수백 라인 기준 30~60분 이상이 걸리고, 근거 누락 위험이 크다. |
| UX 문제 | 여러 질문을 한 번에 받으면 답변 부담이 커지고, 긴 분석 대기 중에는 서비스가 멈춘 것으로 오해하기 쉽다. |
| 신뢰 문제 | 단순 점수나 요약만으로는 어떤 결과물 위치가 어떤 의도와 충돌하는지 판단하기 어렵다. |
| 해결 방향 | 기획안 또는 deep interview로 의도 기준선을 확보하고, 결과물 제출 후 수 분 내 근거 인용 보고서와 개선 제안을 제공한다. |

## 3. 목표 및 비목표 (Goals & Non-Goals)
### 3.1 목표
| ID | 목표 |
| --- | --- |
| G1 | 사용자가 로그인 없이 홈에서 기획안 업로드, deep interview, 샘플 체험 중 하나를 바로 시작할 수 있게 한다. |
| G2 | 항상 한 번에 하나의 활성 질문만 제시하여 답변 부담을 낮추고, 질문 흐름은 마인드맵으로 탐색하게 한다. |
| G3 | 백엔드가 반환하는 가변 길이 질문과 분기 구조를 제한 없이 렌더링한다. |
| G4 | 인터뷰 종료 또는 기획안 업로드 후 결과물 제출 화면에서 파일·링크·GitHub를 다건 제출하고 수집 상태를 확인하게 한다. |
| G5 | 분석 진행 상태를 백엔드 JobStage에 맞춰 `의도·결과물 정리 → 차이 분석 → 보고서 생성`으로 투명하게 전달한다. |
| G6 | 결과 화면에서 IntentDoc, 결과물 근거, 테마별 finding, 지표, 개선 제안을 각주와 교차 강조로 연결한다. |
| G7 | 지표는 개수·비율 기반으로 표시하고, 산정 불가 상태와 사유를 명확히 보여준다. |
| G8 | 새로고침·재접속·다중 탭 상황에서도 서버 상태를 기준으로 안전하게 복구한다. |
| G9 | AI가 생성하거나 보조한 모든 화면 표면에 AI 고지 배지 또는 문구를 표시한다. |

### 3.2 비목표
| ID | 비목표 |
| --- | --- |
| NG1 | 프론트엔드에서 LLM 추론, drift 판정, 파일 파싱, 정량 산식을 직접 수행하지 않는다. |
| NG2 | MVP에서 전문 편집기, 실시간 공동 편집, 세션 간 이력 관리, 사용자 계정 기능을 제공하지 않는다. |
| NG3 | MVP에서 사용자가 질문 노드를 임의 생성·삭제하거나 연결선을 직접 수정하는 기능은 제공하지 않는다. |
| NG4 | 결과물을 자동 수정하거나 외부 저장소에 쓰기 작업을 수행하지 않는다. 개선 제안까지만 제공한다. |
| NG5 | 모바일 전용 앱은 만들지 않는다. 단, 결과 화면·보고서 열람 등 핵심 판독 경로는 모바일 반응형을 보장한다. |

## 4. 사용자 및 이해관계자 (Users & Stakeholders)
| 구분 | 설명 | 프론트엔드에 대한 기대 |
| --- | --- | --- |
| 최종 사용자 | 구조화되지 않은 아이디어나 AI 위임 산출물을 검토하려는 사용자 | 적은 학습 비용, 빠른 시작, 의도 대비 결과물 차이의 근거 있는 보고서 |
| 기획자/PM | 기획안·요구사항과 산출물의 정합성을 확인하려는 사용자 | IntentDoc 기준선, 누락·왜곡 위치, 개선 제안 |
| 개발자/테크 리드 | 코드·GitHub 결과물이 의도와 맞는지 확인하려는 사용자 | 파일·라인·링크 근거, 테마별 심각도, 재작업 우선순위 |
| 심사자 | 로그인 없이 짧은 시간 안에 핵심 기능을 평가하는 사용자 | 샘플 체험 경로, 3분 내 완주 가능한 데모, Azure URL 접근성 |
| 백엔드/AI 에이전트 팀 | 세션, 질문, 결과물, 분석 job, 보고서 API를 제공하는 팀 | 명확한 상태·오류·데이터 계약과 프론트 사전 검증 규칙 |

## 5. 정보 구조 및 핵심 사용자 흐름
### 5.1 전역 구조
| 항목 | 요구사항 |
| --- | --- |
| 화면 셸 | 브라우저 뷰포트 전체 크기로 고정하고, 본문 전체 스크롤 대신 화면 내부 영역만 스크롤·드래그한다. |
| 홈 버튼 | 좌측 상단에 모든 단계에서 식별 가능한 홈 버튼을 고정 배치한다. 진행 중 입력 또는 job이 있으면 확인 모달을 표시한다. |
| 세션 복구 | localStorage에 미만료 세션 토큰이 있으면 홈에서 `이어하기` 배너를 표시한다. |
| 서버 우선 | 다중 탭 또는 stale 화면에서는 서버가 반환한 SessionStatus와 최신 트리를 항상 신뢰한다. |
| 데이터 삭제 | 모든 주요 화면에서 접근 가능한 `내 데이터 지우기` 액션을 제공하고 `DELETE /sessions/{id}` 성공 시 토큰과 화면 상태를 즉시 폐기한다. |

### 5.2 기본 흐름
| 단계 | 사용자 행동 | 프론트 동작 | 다음 상태 |
| --- | --- | --- | --- |
| 1 | 홈 진입 | 세션 생성 또는 기존 토큰 복구. 기획안 업로드, 첫 질문 시작, 샘플 체험 CTA를 표시한다. | INITIAL |
| 2-A | 기획안 업로드 | `.docx/.txt/.md` 파일 사전 검증 후 업로드한다. 업로드 성공 시 인터뷰를 건너뛰거나 단축한다. | SUBMITTING |
| 2-B | 첫 질문 답변 | 질문 카드에 답변을 입력하고 제출한다. 다음 질문 수신 전 스켈레톤 노드를 표시한다. | INTERVIEWING |
| 3 | 연속 질의 | 백엔드가 반환한 `nextQuestions[]`를 트리에 추가한다. 조기 종료 버튼을 제공한다. | INTERVIEWING 또는 SUBMITTING |
| 4 | 결과물 제출 | 파일·링크·GitHub를 다건 제출하고 `ingestStatus` 목록을 확인한다. | SUBMITTING |
| 5 | 분석 시작 | `분석 시작` 액션으로 job을 만들고 대기 화면으로 전환한다. | ANALYZING |
| 6 | 분석 대기 | 2초 폴링과 ETag를 사용해 단계 상태를 갱신한다. 취소 버튼을 제공한다. | ANALYZING 또는 FAILED |
| 7 | 결과 확인 | IntentDoc, finding, evidence, metrics, suggestions를 렌더링한다. | COMPLETED |
| 8 | 다운로드 | IntentDoc과 보고서 Markdown 원문을 클라이언트에서 파일로 생성해 내려받는다. | COMPLETED |

### 5.3 상태 흐름
| 프론트 상태 | 백 SessionStatus | 대표 화면 | 설명 |
| --- | --- | --- | --- |
| INITIAL | CREATED | 홈 | 세션은 있으나 의도 확보 전 상태 |
| INTERVIEWING | INTERVIEWING | 마인드맵 | 질문·답변 진행 중 |
| SUBMITTING | INTERVIEW_DONE | 결과물 제출 | 의도 기준선 확보 후 결과물 제출 대기 |
| ANALYZING | ANALYZING | 분석 대기 | 비동기 job 진행 중 |
| COMPLETED | REPORT_READY | 분석 결과 | 보고서 조회 가능 |
| FAILED | 실패 응답 또는 job 실패 | 오류 상태 | 실패 단계와 재시도/취소/새 세션 액션 표시 |
| EXPIRED | EXPIRED 또는 404 | 만료 안내 | 토큰 폐기 후 `새 세션 시작` CTA 표시 |

## 6. 화면별 디자인 요구사항
### 6.1 화면 1 — 홈, 기획안 업로드 및 첫 질문
| 영역 | 요구사항 |
| --- | --- |
| 시작 선택 | `기획안 업로드`, `질문으로 시작`, `샘플로 체험` CTA를 동일 위계로 제공한다. |
| 질문 설정 | `confuseThreshold`와 `timeLimitSec`를 고급 설정으로 제공하되 기본값으로도 바로 시작할 수 있게 한다. |
| 기획안 업로드 | `.docx/.txt/.md`, 10MB 이하만 허용한다. 업로드 성공 시 추출된 의도 요약과 AI 고지 배지를 표시한다. |
| 샘플 체험 | 번들 샘플 기획안과 샘플 결과물을 자동 제출해 심사자가 약 3분 안에 결과 화면까지 도달하는 데모 경로를 제공한다. |
| 첫 질문 | 질문으로 시작할 경우 첫 질문 카드 하나와 답변 입력 영역만 표시한다. |
| 질문 카드 | `prompt`, `helperText`, 필수/선택 여부, AI 생성 배지, 답변 입력 필드, 제출 버튼을 포함한다. |
| 입력 검증 | 답변은 2,000자 이하, 공백만 입력 불가로 사전 검증한다. |
| rate limit | 세션 생성이 429로 실패하면 `Retry-After` 기반 카운트다운과 재시도 버튼을 표시한다. |

### 6.2 화면 2 — 연속 질의 마인드맵
| 항목 | 요구사항 |
| --- | --- |
| 노드 배치 | 질문 노드는 좌측에서 우측 방향으로 시간 순서 또는 `parentId` 관계에 따라 배치한다. 병합은 표현하지 않는다. |
| 노드 상태 | 완료, 활성, 전송 중, 오류, 선택 상태를 색상·아이콘·텍스트로 함께 표시한다. |
| AI 고지 | `aiGenerated:true` 질문에는 `AI 생성 질문` 배지를 표시한다. |
| 활성 질문 | 한 번에 하나의 노드만 입력 가능하다. 아직 도착하지 않은 질문은 미리 표시하지 않는다. |
| 스켈레톤 | 답변 제출 직후 흐름 끝에 스켈레톤 노드를 표시하고 중복 제출을 막는다. 30초가 지나면 `질문을 정리하는 중입니다. 잠시만 기다려 주세요.` 안내를 추가한다. |
| 남은 질문 | `remainingQuestions`는 잔여 질문 예산 힌트로만 표시하며 정확한 총량처럼 보이지 않게 한다. |
| 조기 종료 | `그만 답하고 넘어가기` 버튼을 제공한다. REQUIRED 미답변이 있으면 목록과 경고 모달을 표시하고, 사용자가 확인하면 강행한다. |
| 캔버스 | 질문 캔버스 또는 핸들만 드래그 가능하며 페이지와 전역 헤더는 고정한다. 입력 필드 조작과 드래그가 충돌하지 않아야 한다. |
| 현재 질문 복귀 | `현재 질문으로 이동` 버튼을 제공하고, 노드를 영구히 잃지 않도록 이동 범위 또는 위치 복원 기능을 제공한다. |
| 접근성 | 키보드로 노드 간 이동, 활성 질문 포커스, 신규 노드 aria-live 알림을 제공한다. 모바일·보조기술 환경에서는 리스트 뷰 폴백을 제공한다. |
| 답변 수정 | MVP에서는 제공하지 않는다. M2에서 도입 시 이후 분기 무효화 안내와 재생성 계약을 따른다. |

### 6.3 화면 3 — 결과물 제출
| 영역 | 요구사항 |
| --- | --- |
| 진입 조건 | 기획안 업로드 완료, 인터뷰 완료, 또는 조기 종료 완료 후 진입한다. |
| 제출 유형 | 파일, 일반 HTTPS 링크, GitHub URL을 다건 제출할 수 있다. |
| 파일 한도 | 결과물 파일은 20MB 이하, 세션당 20건 이하로 사전 검증한다. zip은 해제 후 100MB·1,000개 파일 초과 가능성을 안내하고 백엔드 차단 상태를 표시한다. |
| URL 한도 | 링크는 HTTPS만 허용한다. GitHub 유형은 `github.com` 도메인만 허용한다. |
| 제출 목록 | 각 결과물을 `name`, `type`, `ingestStatus`, `ingestNote`, `submittedAt`와 함께 목록으로 표시한다. |
| 상태 표시 | `PENDING`, `PARSED`, `SKIPPED_UNSUPPORTED`, `SKIPPED_TOO_LARGE`, `BLOCKED_UNSAFE`를 사용자 친화 문구와 아이콘으로 표시한다. |
| 분석 시작 | 최소 1개 이상 제출된 결과물이 있으면 `분석 시작` 버튼을 활성화한다. 차단·제외된 항목은 분석 제외 가능성을 명확히 알린다. |
| 삭제 | 분석 시작 전 제출 항목 제거와 세션 전체 삭제를 구분해 제공한다. |

### 8.1 프론트엔드 데이터 계약 개요
상세 엔드포인트와 스키마는 SCHEMA v0.3을 따른다. 프론트엔드는 아래 필드를 화면 계약으로 사용한다.

| 데이터 | 필수 필드 | 프론트 사용 목적 |
| --- | --- | --- |
| Session | `sessionId`, `status`, `expiresAt`, `activeJobId?`, `interviewStartedAt?` | 상태 라우팅, TTL 표시, job 폴링 재개 |
| SessionStatus 매핑 | `CREATED`, `INTERVIEWING`, `INTERVIEW_DONE`, `ANALYZING`, `REPORT_READY`, `EXPIRED` | INITIAL, INTERVIEWING, SUBMITTING, ANALYZING, COMPLETED, EXPIRED 화면 전환 |
| QuestionNode | `questionId`, `parentId`, `depth`, `prompt`, `helperText?`, `kind`, `status`, `confused?`, `intentPhase`, `inputType:"text"`, `aiGenerated:true`, `createdAt` | 질문 카드, 트리 렌더링, AI 고지, 필수 질문 경고 |
| Answer submit response | `nextQuestions[]`, `remainingQuestions`, `interviewStatus`, `completedReason?` | 다음 노드 추가, 잔여 질문 힌트, 제출 화면 전환, 종료 사유 표시 |

| Artifact | `artifactId`, `type`, `name`, `url?`, `ingestStatus`, `ingestNote?`, `submittedAt` | 결과물 제출 목록과 수집 상태 표시 |
| Job status | `jobId`, `stage`, `status`, `progress?`, `error?`, `etag` | 3단계 대기 화면, 2초 폴링, ETag 캐시, 실패 재시도 |
| Job cancel | `POST /jobs/{jobId}/cancel` | 분석 취소 버튼과 fetch abort 처리 |
| Report | `metrics[]`, `quantStats`, `qualitative(markdown)`, `suggestions[]`, `findings[]`, `intentDoc`, `normalizationSchema`, `aiGeneratedNotice`, `earlyCompleted?` | 결과 화면 전체 데이터 |

| EvidenceRef | `artifactId`, `location{kind,path?,startLine?,endLine?,url?,note?}`, `quote` | 결과물 위치 표시, 인용문, 근거 이동 |
| Metric | `metricId`, `label`, `value`, `unit`, `thresholds?`, `status`, `description`, `computable`, `reason?` | 지표 카드, 차트, 산정 불가 표시 |

### 8.2 프론트 사전 검증 상수
| 항목 | 값 | 실패 시 동작 |
| --- | --- | --- |
| 기획안 파일 | `.docx/.txt/.md`, 10MB 이하 | 업로드 전 차단 및 허용 형식 안내 |
| 결과물 파일 | 파일당 20MB 이하, 세션당 20건 이하 | 제출 전 차단 및 초과 항목 표시 |

| 일반 URL | HTTPS만 허용 | 입력 단계에서 차단 |
| GitHub URL | `github.com`만 허용 | 입력 단계에서 차단 |
| confuseThreshold | 0~1, step 0.05 | 범위 밖 값 저장 차단 |
| timeLimitSec | 60~3600초 또는 미설정 | 범위 밖 값 저장 차단 |

| 첫 질문 조회 실패 | 오류 원인과 `다시 불러오기`를 표시한다. |
| 답변 제출 실패 | 입력값을 보존하고 동일 답변을 재시도할 수 있게 한다. |
| 다음 질문 생성 지연 | 스켈레톤 상태를 유지하고 30초 이후 안심 문구를 표시한다. |
| REQUIRED 미답변 조기 종료 | 미답변 목록을 모달에 표시하고 `그래도 넘어가기` 확인을 받는다. |
| 결과물 제출 실패 | 실패 항목만 재시도 가능하게 하며 성공 항목은 유지한다. |
| 분석 취소 | 취소 완료 후 결과물 제출 화면으로 돌아가거나 새 세션을 시작할 수 있게 한다. |
| SESSION_EXPIRED / SESSION_NOT_FOUND | localStorage 토큰을 폐기하고 `새 세션 시작` CTA를 표시한다. |
| 분석 실패 | 완료 단계는 보존하고 실패 단계부터 재시도한다. |
| 결과 일부 누락 | 사용 가능한 결과는 표시하되 누락 영역과 원인을 명시한다. |
| 연결 끊김 | 오프라인 상태를 알리고 연결 복구 후 서버 상태를 재조회한다. |

## 11. 제약 및 가정 (Constraints & Assumptions)
### 11.1 제약
| ID | 제약 |
| --- | --- |
| CON-1 | React 기반 웹 애플리케이션으로 구현한다. |
| CON-2 | Copilot SDK와 Microsoft Agent Framework는 백엔드 agent 로직의 필수 구성요소이며, 프론트는 해당 결과를 표시하는 클라이언트다. |
| CON-3 | 최종 산출물은 Azure 클라우드에 배포된 웹앱이어야 한다. 프론트 정적 번들은 백엔드 컨테이너에서 단일 URL로 서빙한다. |
| CON-4 | 로그인 없이 동작해야 하며, 세션 토큰만으로 핵심 흐름을 식별한다. |
| CON-5 | 세션 TTL은 마지막 활동 기준 24시간이며, 보고서 도달 시 72시간으로 연장한다. |
| CON-6 | 사용자는 `내 데이터 지우기`로 세션과 제출 데이터를 즉시 파기할 수 있어야 한다. |
| CON-7 | 질문 트리는 분기만 표현하며 병합은 표현하지 않는다. |
| CON-8 | 결과 화면의 데스크톱 기본 비율은 좌측 30%, 우측 70%다. |
| CON-9 | 프론트는 metric 임계값·상태 기준을 하드코딩하지 않는다. |
| CON-10 | 세션 생성은 IP당 분당 5회로 제한되며, 429 응답 시 카운트다운 UI를 제공한다. |

### 11.2 가정
| ID | 가정 |
| --- | --- |
| A-1 | 백엔드는 각 질문의 고유 ID, 부모 관계, 필수 여부, AI 생성 여부, 종료 신호를 일관된 형식으로 제공한다. |
| A-2 | 기획안 업로드가 성공하면 백엔드는 IntentDoc 생성에 필요한 의도 정보를 확보하거나 인터뷰 단축 상태를 제공한다. |
| A-3 | 분석 결과에는 IntentDoc blockId와 finding의 `intentBlockIds[]`, evidence 위치 정보가 포함된다. |
| A-4 | 분석 지표에는 값뿐 아니라 상태 기준, 단위, 설명, 산정 가능 여부와 사유가 포함된다. |
| A-5 | 분석 작업은 비동기로 수행되며 job ID와 ETag로 상태를 재조회할 수 있다. |
| A-6 | 완료된 보고서는 TTL 내 동일 세션 토큰으로 다시 접근할 수 있다. |

## 14. 수용 기준 (Acceptance Criteria)
| ID | 기준 |

| AC-9 | 인터뷰 완료 또는 기획안 업로드 후 결과물 제출 화면으로 이동한다. |
| AC-10 | 결과물 제출 화면은 파일·HTTPS 링크·GitHub URL 다건 제출과 수집 상태 목록을 제공한다. |

| AC-12 | 분석 대기 중 취소 버튼이 동작하며 완료 후 제출 화면 또는 새 세션 시작으로 이동할 수 있다. |
| AC-13 | 새로고침 후에도 서버 상태에 따라 홈, 마인드맵, 제출, 대기, 결과 화면 중 적절한 화면으로 복구된다. |

| AC-15 | 모바일에서 결과 화면과 보고서 열람이 세로 레이아웃으로 가능하다. |
| AC-16 | IntentDoc blockId와 finding evidence가 프론트 파생 각주로 연결된다. |

| AC-22 | `내 데이터 지우기` 성공 후 localStorage 토큰과 화면 상태가 제거된다. |
| AC-23 | 키보드만으로 시작, 질문 답변, 제출, 결과 상세 탐색까지 핵심 흐름을 수행할 수 있다. |
